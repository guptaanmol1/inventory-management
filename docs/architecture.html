Factory Inventory Management System

Architecture overview: a Vue 3 single-page dashboard backed by a FastAPI service that serves read-only, in-memory mock data. There is no database.

System architecture

Three tiers, all running locally. The browser talks to the API directly over HTTP (CORS is open).

Tech stack

Versions are the minimums declared in package.json and pyproject.toml.

Frontend

  • Vue 3 (Composition API)
  • Vue Router 4
  • Vite 8 (dev server on 3000)
  • Axios for HTTP
  • Custom SVG charts, CSS Grid layouts
  • Node ^20.19 or >=22.12

Backend

  • Python 3.11+
  • FastAPI
  • Uvicorn (port 8001)
  • Pydantic 2 for response models
  • uv for dependency management

Data

  • JSON files in server/data/
  • Loaded once at import by mock_data.py
  • Sample data generated by generate_data.py
  • No database, no writes

Tooling

  • pytest + FastAPI TestClient (backend tests)
  • httpx, pytest-cov
  • scripts/start.sh, stop.sh
  • i18n: English and Japanese

Data flow

How a filter change on screen becomes a re-rendered chart.

  1. Filter changeFilterBar updates shared refs in useFilters (period, location, category, status). The refs are module-level, so every view sees the same state.
  2. Build queryA view calls getCurrentFilters(), which maps period to month and location to warehouse, then passes the result to api.js. Values equal to all are omitted from the query string.
  3. RequestAxios sends GET http://localhost:8001/api/...?warehouse=&category=&status=&month=. Views fetch several endpoints in parallel (the Dashboard uses four).
  4. Filter in memoryThe FastAPI handler runs apply_filters and filter_by_month over the Python lists loaded from JSON. The dashboard handler also aggregates totals (inventory value, low stock, pending orders).
  5. Validate and respondPydantic response_model checks the shape, and FastAPI returns JSON.
  6. RenderThe view stores the raw response in refs (for example allOrders, inventoryItems). Computed properties derive chart and table data, and the template redraws.

Things worth knowing

  • The API base URL is hardcoded in client/src/api.js as http://localhost:8001/api, so it is not configurable per environment.
  • CORS allows any origin. This is fine for a local demo and should be tightened before any real deployment.
  • Data is read-only and loaded at startup. Edit the JSON files and restart the server to change it.
  • Inventory has no time dimension, so the month filter applies to orders only.
  • views/Backlog.vue exists but has no route in main.js. The Dashboard reads backlog data through api.getBacklog() instead.
  • Authentication is mocked: useAuth returns a fixed user and there is no login.
